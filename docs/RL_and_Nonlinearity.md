# 项目中的非线性项处理与为何使用 RL

## 1. 现有项目里非线性项是怎么做的？

### 动力学：**显式建模，全部保留**

在 `core/dynamics/auv_dynamics.py` 中，AUV 采用完整的 6DOF 非线性模型（Fossen 形式）：

```
M·ν̇ + C(ν)·ν + D(ν)·ν + g(η) = τ
```

- **M**：惯性矩阵（刚体 + 附加质量）
- **C(ν)**：科里奥利/向心力矩阵，**依赖速度 ν，为非线性**
- **D(ν)·ν**：阻尼 = 线性项 D_l·ν + **二次阻尼** D_q·|ν|·ν，**二次项为非线性**
- **g(η)**：重力/浮力恢复力
- **τ**：推进器产生的力/力矩

也就是说：**非线性项（C、二次阻尼）在仿真里被完整写出并参与积分**，没有在建模阶段被“规避”或线性化。仿真用的是带非线性的真实动力学。

### 控制器：**线性 PID，不显式抵消非线性**

`core/control/dual_loop_pid.py` 中的控制逻辑是：

- **速度环**：`force_cmd = Kp_vel * (desired_vel - current_vel) - Kd * current_vel`（线性 PD）
- **姿态双环**：外环 PI（角度误差 → ω_ref）+ 内环 PD（角速度误差 → 力矩），外加前馈和 ESO 扰动估计

控制器**没有**做反馈线性化（即没有用模型把 C(ν)、D(ν) 显式抵消掉）。非线性留在被控对象里，由**线性 PID** 去“扛”，靠增益和 ESO 等提高鲁棒性。

### 小结：谁在“处理”非线性？

| 环节       | 非线性项     | 处理方式                         |
|------------|--------------|----------------------------------|
| 动力学仿真 | C(ν), D(ν) 等 | **全部显式建模**，RK4 积分       |
| 控制器     | -            | **线性** PID，不显式抵消 C/D     |
| RL         | -            | 只选**高层离散动作**（前进/转弯等） |

所以：**非线性在环境（动力学）里被如实仿真；控制层是线性 PID；RL 只负责“何时往哪动”，不直接算力矩或补偿非线性。**

## 2. 为什么还想用 RL？（规避的是哪一类“非线性处理”）？

这里的“规避”主要指的是：**不在控制层对复杂/不确定非线性做精确建模与解析补偿**，而是用学习来适应。

- **传统做法**：若要“处理好”非线性，往往要  
  - 精确已知 C(ν)、D(ν) 等，做反馈线性化或非线性控制律设计，或  
  - 对不确定项做观测器（如 ESO）并补偿。  
  对复杂/欠标定系统，这类**解析的、针对非线性的设计**成本高、易失配。

- **本项目的做法**：  
  - **动力学**里非线性照常写进仿真（C、二次阻尼等都在）。  
  - **控制**用固定结构的线性 PID（+ ESO 等），不要求控制器显式“算清”所有非线性。  
  - **RL 学的是高层策略**：在什么状态下选“前进/左转/悬停”等离散动作，使 PID 跟踪的目标更合理，从而在**存在非线性的闭环**里也能表现好。

因此，“用 RL 规避对非线性项的处理”更准确的理解是：  
**不在控制层做复杂的、针对非线性的解析设计，而是把“决策”交给 RL，在带非线性的仿真中学习高层策略，让线性 PID 只做底层跟踪。**

## 3. 和 2D 追逃的关系

- **pe_v2 动力学版**（当前）：RL 直接输出**推力方向**（离散 9 个），动力学用同一套 M·a = τ − D·v − D·|v|·v 积分，**没有** 2D 的 PID。
- **pe_v2 + 2D 双环 PID 版**（新加）：为和现有 low_level 输出逻辑一致，改为  
  **RL 只输出目标点/目标航向 → 2D PID 根据目标与当前状态算 τ → 同一套 2D 动力学积分 → 观测里包含速度、加速度**。  
  这样 2D 追逃的“谁决策、谁算推力”和 6DOF 的“RL 高层 + PID 算推力”一致，便于对比和迁移。
